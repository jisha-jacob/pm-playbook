# PM Playbook

A RAG application for the [DataTalksClub LLM Zoomcamp](https://github.com/DataTalksClub/llm-zoomcamp).

## Problem

Lenny's Podcast features world-class product leaders, but actionable advice is buried in 300+ long-form transcripts. PM Playbook lets users ask natural-language questions and get synthesized, cited answers.

## Data

Transcripts from [ChatPRD/lennys-podcast-transcripts](https://github.com/ChatPRD/lennys-podcast-transcripts). For personal/educational use only.

## Quick Start

```bash
# 1. Install dependencies
uv sync

# 2. Set your OpenAI API key
export OPENAI_API_KEY="your-key"

# 3. Run ingestion
python -m pm_playbook.ingest

# 4. Start the app
streamlit run streamlit_app/Home.py

## Phase 1: Ingestion Pipeline

The ingestion pipeline converts the raw Lenny's Podcast transcripts into a clean, retrieval-ready dataset for the RAG application.

### Pipeline overview

```text
transcript.md
      ↓
Parse YAML frontmatter
      ↓
Create Episode model
      ↓
Parse speaker turns
      ↓
Merge short consecutive turns
      ↓
Split long turns at sentence boundaries
      ↓
Remove standalone backchannels
      ↓
Flag sponsor and promotional content
      ↓
Validate chunks
      ↓
data/chunks.parquet
```

### Supported transcript formats

The speaker parser supports all transcript formats found during Phase 0 inspection:

```text
Speaker Name (HH:MM:SS): Dialogue
Speaker Name (MM:SS): Dialogue
Speaker Name: Dialogue
(HH:MM:SS): Continuation from the previous speaker
(MM:SS): Continuation from the previous speaker
```

Bare timestamp lines inherit the most recently identified speaker.

### Chunking behavior

The ingestion pipeline:

* preserves speaker-level context;
* merges short consecutive turns from the same speaker;
* splits long speaker turns at sentence boundaries;
* limits chunks to a maximum of 300 words;
* removes standalone conversational backchannels such as `Yeah`, `Right`, and `Exactly`;
* preserves useful short statements;
* assigns deterministic episode and chunk IDs;
* records each chunk's position within its episode;
* attaches episode metadata, speaker information, timestamps, and word counts.

### Sponsor-content handling

Sponsor and promotional sections are detected using general sponsorship and promotional signals rather than a hard-coded list of advertiser names.

Examples of detection signals include:

```text
brought to you by
sponsored by
thanks to our sponsor
use code
promo code
free trial
percent off
```

Sponsor-related chunks are preserved in the output with:

```text
is_sponsor_read = True
```

They can be excluded later when building the retrieval index without permanently removing them from the processed dataset.

### Duplicate handling

Some dataset folders contain duplicate copies of the same YouTube episode.

The ingestion pipeline uses the YouTube `video_id` as the primary episode identifier and skips repeated episodes during ingestion. This prevents duplicate transcript content from entering the retrieval and evaluation datasets.

### Missing metadata handling

Most transcript files contain complete YAML frontmatter. For the small number of files with missing metadata, the parser applies the following title fallback order:

1. YAML `title`
2. First level-one Markdown heading
3. Episode folder name

This allows the full corpus to be processed without adding episode-specific exceptions.

### Run the ingestion pipeline

From the project root:

```bash
uv run python -m pm_playbook.ingest --fail-fast
```

The command processes the full transcript corpus and writes:

```text
data/chunks.parquet
```

### Run a smoke test

To process only the first three transcript files:

```bash
uv run python -m pm_playbook.ingest \
  --limit 3 \
  --output data/chunks-smoke-test.parquet \
  --fail-fast
```

A larger quality-review sample can be generated with:

```bash
uv run python -m pm_playbook.ingest \
  --limit 20 \
  --output data/chunks-quality-test.parquet \
  --fail-fast
```

### Output schema

Each row in `data/chunks.parquet` represents one retrieval-ready chunk.

| Column            | Description                                                        |
| ----------------- | ------------------------------------------------------------------ |
| `chunk_id`        | Deterministic identifier for the chunk                             |
| `episode_id`      | Deterministic identifier for the source episode                    |
| `chunk_index`     | Global position in the processed dataset                           |
| `chunk_position`  | Position within the source episode                                 |
| `guest`           | Podcast guest name                                                 |
| `episode_title`   | Episode title                                                      |
| `publish_date`    | Episode publication date                                           |
| `youtube_url`     | Source YouTube URL                                                 |
| `video_id`        | YouTube video identifier                                           |
| `speaker_name`    | Speaker associated with the chunk                                  |
| `start_time`      | Approximate chunk start time in seconds                            |
| `end_time`        | Approximate chunk end time in seconds                              |
| `text`            | Chunk text                                                         |
| `word_count`      | Number of words in the chunk                                       |
| `is_sponsor_read` | Whether the chunk was classified as sponsor or promotional content |

### Validation checks

Before writing the Parquet file, the pipeline validates that:

* chunk IDs are unique;
* global chunk indexes are continuous;
* chunk positions are continuous within each episode;
* chunks contain nonempty text;
* stored word counts match the chunk text;
* no chunk exceeds 300 words;
* standalone backchannels are excluded;
* duplicate source episodes are skipped.

### Processed artifact

The generated file is approximately **13.78 MB** and is committed to the repository so that reviewers can run retrieval experiments without first rebuilding the ingestion dataset.

The artifact can be regenerated at any time with:

```bash
uv run python -m pm_playbook.ingest --fail-fast
```
